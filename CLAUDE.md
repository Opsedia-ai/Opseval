# CLAUDE.md: working on Opseval

Read this first in every session. It is the shared context for anyone (human or agent) contributing to this repo.

## What Opseval is

Open-source, black-box evaluation for conversational AI agents. An LLM (or a script) plays the customer. The conversation runs over the agent's real protocol. The simulated customer answers approval checkpoints. Every attempt is recorded, then scored by deterministic checks and quote-backed LLM judges. Repeated attempts fold into verdicts, then a release gate and CI exit codes.

Business model: open core, like Langfuse. The Apache-2.0 core lives here. Commercial Enterprise features go under `ee/` behind a licence key, and there will be a managed Cloud edition. The pledge in `GOVERNANCE.md` holds: evaluation features never move behind a licence key.

## The one rule that shapes every change

> A harness problem must never look like an agent failure, and a real agent failure must never be hidden as "not measured".

- Scores are `passed | failed | infra_error`. `score is None` exactly when the status is `infra_error` (validated in `ScoreResult`).
- Verdicts are `passed | failed | inconclusive | skipped_precondition | blocked`.
- Exit codes: `0` pass · `1` fail · `2` not judged · `3` harness/config error.
- Anything under `HarnessError` (transport, simulator, LLM, trace source) is never the agent's fault. A `TransportTimeout` *is* the agent's fault.
- An unmeasured value renders as "not measured", never as 0.
- Committed-outcome guard (ADR-0008): the default `stop_at` is `commit_gate`. The irreversible outcome needs `allow_commit: true` in the scenario **and** `--allow-commit` on the run.

When you add a transport, scorer or trace source, add fault-injection tests that prove both halves of the rule (see `tests/test_driver_and_faults.py`).

## Commands

```bash
uv sync                      # install (Python 3.11+)
make check                   # ruff, import-linter, bandit, mypy --strict, pytest (coverage >= 85%)
make audit                   # network: pip-audit + licence allowlist on runtime deps from uv.lock
uv run opseval demo          # healthy agent → exit 0
uv run opseval demo --bug skip-approval   # → exit 1   (also: forget-method → 1, crash → 3)
uv run opseval init /tmp/x && uv run opseval validate /tmp/x/suites/full.yaml --profile /tmp/x/profile.yaml

uv run opseval serve --target ws://127.0.0.1:8765   # API on :8000 (loopback only, no auth yet)
make db-up                   # Postgres for server mode and its tests (127.0.0.1:5433); prints the env to export
make console                 # the web console on :5173, proxying /api to :8000 (needs Node 22.22+ or 24.15+)
make console-check           # typecheck + build the console (runs in CI)
docker build -t opseval . && docker run --rm opseval demo   # the CLI image (ADR-0038)
uv run mkdocs serve          # the docs site (ADR-0039); `make docs` builds it strictly
uv run python scripts/reference_docs.py   # after changing a scorer or a setting
```

Definition of done for any change: `make check` is green (which now includes `opseval schemas --check`, so run `opseval schemas` after touching a model), coverage stays ≥ 85%, and the four demo exit codes are unchanged. New behaviour comes with tests, plus docs (README, ROADMAP or ADR) when a user would notice it. **Every PR that changes what Opseval can do updates `docs/STATUS.md`** (the row's status and evidence, and the "As of" line), then runs `uv run python scripts/project_status.py` to recompute the percentages; `make check` fails if they are stale. **`docs/ATTENTION.md`** (decisions only the maintainers can make, and critical/high issues) is updated in the same PR whenever one is raised or settled.

## Conventions

- Python 3.11, `mypy --strict`, ruff (line length 100). Pydantic v2 models with `extra="forbid"`. Authoring mistakes must fail at load time.
- Every settings value goes through `config.Settings` (`OPSEVAL_*`). No other module reads the environment. Secrets are `SecretStr` and appear in `SECRET_FIELDS`, and `config_digest` redacts them.
- Any host that receives a conversation or a key must be in `OPSEVAL_ALLOWED_HOSTS` and use TLS unless it is loopback (`check_url_allowed`).
- Scorers never raise to the engine. The engine turns exceptions into `infra_error` anyway, but return `self.infra(...)` with a `REASON_CODE: explanation`.
- Tool scorers report `details.source` (`trace` or `frames`) and set `degraded` for frame evidence.
- Commits: Conventional Commits (`feat(scope): ...`), DCO sign-off for external contributors.
- Keep the repo **private** until Gate 0 (IP clearance) is signed off. Never copy code, prompts, scenario content or names from any employer's internal systems (clean-room policy).

- v0.2: `--transport sse` for agents that stream a turn as Server-Sent Events. A stalled stream is a `TransportTimeout` (the agent's fault); a dropped one is `TransportClosed` (not judged); an undecodable event stays `_raw` and is never given a kind, so garbage cannot look like a clean turn (ADR-0019).

A **dependency** outage skips only the scenarios it silences (`skipped_precondition`); an **unreachable agent** raises `ConfigError` (exit 3) rather than skipping, because a skip is only a gate warning and would report "safe to release" on a suite that tested nothing. `opseval preflight` runs the checks alone; `--no-preflight` and `--verify-llm` on `run` (ADR-0020).
- v0.1: telemetry is implemented and **ships dark** — no default endpoint, so nothing is sent until an operator sets `OPSEVAL_TELEMETRY_ENDPOINT` *and* allowlists it. Payload is a `extra="forbid"` model, counts are bucketed, non-built-in names become `custom`, and an import contract plus a sentinel test keep conversation content out. Off via `OPSEVAL_TELEMETRY=false`, `DO_NOT_TRACK=1`, `CI=true` or `opseval telemetry disable` (ADR-0021). PR #12 is still the design record to review.
- v0.2: scorer plugins via the `opseval.scorers` entry-point group. Discovery **fails closed**: an unimportable plugin, a contract violation or an id collision is a `ConfigError` (exit 3), never a skip — a skipped scorer becomes `UNKNOWN_SCORER`, an `infra_error`, which `attempt_verdict` drops from `measured`, so the suite would go green with the check gone. `opseval.testing.ScorerContract` is the public kit; it claims only what `ScoreResult` does not already validate (ADR-0022).
- v0.2: flow map in the HTML report — per attempt, expected vs observed phase transitions, opening itself when the path was not clean. No phases or no markers is *not measured* with the reason, never an empty diagram. It changes no status, score or exit code; `flow.phase_order` still decides. `render_html` takes an optional profile for the declared order (ADR-0023).
- v0.2: `tools.args_valid` checks a call's arguments against the tool's `args_schema` (JSON Schema, needs full trace coverage; frames never carry arguments). No declared schema is `NOT_MEASURABLE`, a broken schema is reported as the *schema* being broken, and a called tool without one is `unchecked`, never failed. A **vacuous** pass (the situation never arose) is now named in the gate summary, JUnit, console and HTML — it was only in `details` before, so five scorers could pass on no evidence and look identical to a real pass. It changes no status or exit code (ADR-0024).
- v0.2: protocol probes (`profile.probes`) run in the driver's PROBES state, after connect and before the opening message, graded by `protocol.probes_passed`. They never abort the conversation. No answer is a failed probe (the agent's fault); a transport error is `transport_failure` (not judged); declared-but-never-run is `NOT_MEASURABLE`. An **error reply fails even an empty expectation** unless the probe declares `expect.kind: error` — found against the reference agent, which answers an unknown frame with `error: unknown_frame` (ADR-0025).
- v0.1/v0.2: JSON Schemas for scenario, suite, profile, record and result are generated from the models into `schemas/v1/` (FR-RPT-02, FR-CAT-11). The models are the source of truth and **drift is a failure**: `opseval schemas --check` runs in `make check` and CI, because a stale schema would have an editor accept a file the loader rejects. Generated `by_alias`, so `schema` not `schema_`. `opseval init` writes the `yaml-language-server` hint (ADR-0026).
- v0.1/v0.5: credential **values** are redacted from `FrameRecord.text` and from payload strings before a record is written (`redaction.py`, ADR-0033). `driver.redact` only ever removed credential-shaped *keys*, so a token pasted into a chat turn reached `report.html` and every webhook. Two rules: **credentials, never PII** — an email or order id is the subject matter of the conversation and removing it would leave judges unable to grade it — and **a redaction must not hide an agent's failure**, so the value becomes `[redacted:<kind>]`, the judge transcript explains the marker is proof the credential was said, and `security.no_injection_takeover` still fails the leak. `output.language_script` strips markers before counting script, or the harness's own edit would mark an Arabic agent down. `RunRecord.redaction.applied` defaults to `False` so an old record reads as *unchecked*, not *clean*. Precision over recall: unrecognised token formats pass through.
- v0.5: sinks publish a finished run (`OPSEVAL_WEBHOOK_URL`, `OPSEVAL_LANGFUSE_PUSH_SCORES`). A sink can **never** change a verdict or exit code — every failure is caught — but it must **not** fail silently either: failures land in `result.sinks`, the console and the gate summary, because a sink was asked for. Destinations are allowlisted before the run (exit 3). An unmeasured verdict is pushed as a *category*, never as 0, since a 0 on a dashboard reads as an agent failure (ADR-0027).
- v0.5: `traces.source: otlp-file` reads the OTLP-JSON the OpenTelemetry Collector's file exporter writes (`OPSEVAL_OTLP_SPANS_PATH`), so tool calls can be verified without Langfuse (R-08). OTLP has no query API, so a backend fetcher is deliberately not built — the reusable part is the span→ToolCall mapping. An **empty list is a positive claim** ("the agent called no tools"), so unreadable spans raise `TraceUnavailable` rather than returning `[]`. Only OTLP status 2 (ERROR) is a failure; UNSET is not (ADR-0028).
- v0.5: `opseval serve` (the `serve` extra) exposes the run folders and the catalogue over HTTP, and `packages/console/` is the React console on top of it (ADR-0029). Writes are four and fail closed: starting a run (the ADR-0008 commit guard untouched), one simulator turn (no agent, no test account), saving a suite, and an all-or-nothing import that never overwrites an existing id. - Core rule, timing and commit guard: the driver takes simulator time off the agent's attempt deadline (each call has its own `OPSEVAL_SIMULATOR_TIMEOUT_SECONDS` limit; overrunning it is a `SimulatorError`). A profile with `committed_outcome` but no `commit_gate` fails to load. Ctrl-C exits 130 (`typer>=0.15`), never 1 (ADR-0030 update, ADR-0008 amendment).
- Reading the reply, on the agent's clock (ADR-0042): `protocol.replies_read` (harness axis) runs on every attempt via `scoring.ALWAYS_ON` (added by the engine, **not** in `effective_specs`, so it never changes which dependencies a scenario needs); it fails when the agent sent frames and the profile read nothing, or when frames classified as messages never had the text field (presence counts: `""`/`null` are read); probe answers are not counted. The engine always uses its own spec (a listed `threshold: 0` cannot weaken it); the id is `models.results.UNREAD_REPLIES`. Any failed harness-axis score invalidates the attempt, except that with only unread replies a trace-proven failure or a failed check on a `TIMEOUT` still fails it; every attempt lost or unread → exit 3. `Session.send(frame, *, timeout=)` carries the turn (or probe) timeout; http-json/openai-chat bound the whole turn with `asyncio.timeout` + `transport.base.turn_timeout`. `Session.replies_in_send` (request/response) → a sent frame and the latency clock are stamped *before* `send()`; websocket → when `send()` returns (it may reconnect first). A timed-out or cut-short send still records the frame, the turn and the checkpoint decision.

Policies act between scenarios only. Not-run scenarios are `skipped_precondition` with `skip_kind` `fail_fast|stopped|cancelled`; a scenario a cancel cuts short never passes on part of its repeats: `verdicts.fold_cut_short` fails it if it would fail even had every remaining attempt passed, else skips it as cancelled, keeping its attempts and `cut_short_of` so `rescore` applies the same rule. A stop that left nothing out leaves `stopped` unset. `SuiteResult.stop`/`.stopped`, named in every output. Rate limits are typed (`RateLimited` marker → driver note `rate_limited`), never read from error text. Console: `POST /runs/{id}/cancel` (409 `RUN_NOT_RUNNING` unless running), `progress.cancelRequested`, `LaunchIn.stop` (null keeps the suite's field), `SuiteIn/SuiteOut.stop`, run detail `stopPolicy`/`stopped`/`skipKind`/`cutShortOf`; the shared `StopEditor` names each fallback.

Any new record field bumps `storage.LAYOUT` (now `opseval-runs/2`; 1 still read).
- Test-tenant pool and lanes (ADR-0041, FR-RUN-08/FR-SAF-03): `--tenants tenants.yaml --lanes N` (`tenants.py`, `models/tenant.py`, schema `tenants`). One exclusive `O_EXCL` file lease per scenario in a machine-wide lock dir keyed by the pool's ids (`OPSEVAL_TENANT_LOCK_DIR` to share); unreadable means held; stale only after `OPSEVAL_TENANT_STALE_AFTER_SECONDS`; reclaim by atomic rename; every lease has a `lease_id`; a steal verifies it moved the stale lease it judged (else restores via no-clobber `os.link`); heartbeats cover the whole hold (acquire to release), every 30 s, each awaited before the block returns, writing only while the file is still theirs, otherwise the lease is `lost` and its attempts are not judged; `stale_after` ≥ 90 s. Lanes = min(tenants, requested, `OPSEVAL_LANE_CAP`); `--lanes` without a pool is refused. Tokens via `token_env` → `Settings.secret_named` (reads `.env` too); a minting profile needs a `token_env` per tenant. The runner's `run_one(scenario)` holds every rule; lanes = `asyncio.Semaphore` over it in a `TaskGroup` (first error re-raised as itself); tenants must be distinct identities; each tenant target is preflighted; stop policies stop new scenarios only; results keep catalogue order. An injected transport factory stays one-argument and cannot be combined with a pool.
- Credential providers (ADR-0046, FR-RUN-03): entry-point group `opseval.credentials`, used only when named in `OPSEVAL_CREDENTIALS` (only that one is imported); `CredentialProvider.token_source(CredentialContext(profile, target, tenant, value)) -> TokenSource` (plain def; `value` = `Settings.secret_named`, reads `.env`); `FetchedTokens` caches `fetch() -> (token, ttl)`. Missing/broken/abstract/async/raising-constructor = `ConfigError` (exit 3). The runner wraps it in `GuardedTokens` (lazy): anything raised, or an empty token, is `CredentialsError(HarnessError)` naming provider + exception type only (a provider's `TimeoutError` must never reach SSE's timeout = agent fault). Precedence: tenant `token_env` > provider > HS256/static; profile `token:` + provider is refused. With a provider, pool tenants need no token_env/target (identity `credentials:<id>`). Preflight asks for one token. A profile with no `auth_frame` (WS) never consults it.
- Egress and secrets: every LLM endpoint is allowlisted, keyed or not (a local model needs `127.0.0.1` in `OPSEVAL_ALLOWED_HOSTS`), and preflight never probes a host that is not (a refused host is exit 3, for `opseval preflight` too). Only the LLM roles a suite uses are built. Allowlist errors show only scheme and host. `OPSEVAL_WEBHOOK_URL` is a `SecretStr`; sink outcomes name only the host. Plugin sinks publish only when named in `OPSEVAL_SINKS` (entry-point names; nothing else is imported). Actions are SHA-pinned (Dependabot keeps them current), checkout keeps no credentials, and `release.yml` runs `make check` on 3.11–3.13, the four demo exit codes and `scripts/check_release.py` (tag, both versions and pytest-opseval's `opseval` pin agree) before building both packages.
- Console run detail shows each attempt's conversation: `GET /api/v1/runs/{run}/attempts/{test}/{n}` maps the (already redacted) record's frames to typed entries (message/checkpoint/decision/result/error/notification), tool calls, harness errors and connection events; `redactionChecked: false` marks a record written before value redaction (never checked, not "clean").
- Live progress: the runner writes `progress.json` itself (`opseval.progress.ProgressLog`, model in `models/progress.py`): each scenario waiting/running/done/skipped with attempts, the current one, and a `finishing` stage while the gate, reports and sinks are written. Nothing infers it from other files. A running `RunSummary` carries it, and `GET /runs/{id}` answers 409 `RUN_IN_PROGRESS` with it in `detail.progress`. Never a verdict until `result.json`.
- Scenario editor: files are addressed by catalogue path (`GET/PUT /api/v1/scenarios/source?file=…`; `GET /scenarios/{id}/source` resolves an id), so broken files open too. Validation is `catalogue.check_scenario_text` (the loader's own checks, shared with import) plus id clashes, renames that would empty a suite, and new-file name checks. A save holds a per-file lock over the etag check and the write (409 `SCENARIO_CHANGED`), keeps CRLF and permissions, and uses a cached id index rebuilt only when a scenario file changes.
- v0.2: gate policy per suite (ADR-0032): `gate:` in the suite YAML (`preset: strict|standard|lenient` + per-outcome `block|warn|ignore`), `--gate PRESET` on `run`/`rescore`. Facts stay fixed; policy is recorded on `Gate.policy` and named in every output, with anything looser than standard flagged. Never configurable: nothing judged blocks; exit 3 stays 3; a blocking gate never exits 0; "Safe to release" (`Gate.safe`) needs every scenario passed under any policy; `commit_guard` cannot block; `inconclusive`/`load_errors` cannot be ignored. `--fail-fast` stops only on a failure the policy blocks and records the rest as `skip_kind: fail_fast`. `TestVerdict.skip_kind` tells outages from the commit guard. The console edits a suite's gate (`GET /api/v1/gate` offers only loader-valid choices; `POST /api/v1/gate/resolve` previews; the browser resolves nothing). `standard` = previous gate, except a flaky pass is now a gap.
